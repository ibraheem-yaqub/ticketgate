Payment flow

Six steps.One request.

Press play, or pick a step. The diagram follows along.

illustrative · simulated

  1. Request

    The agent sends a plain HTTP GET. No key, no account, no session.

  2. 402 Quote

    The gate answers 402 Payment Required with a quote: price, asset, chain, pay-to address, nonce and a 30-second expiry.

  3. Policy check

    Before signing anything, the agent checks its own rules: per-call cap, daily cap, endpoint allowlist, kill switch.

  4. Pay the toll

    The agent pays the quoted amount in a USD stablecoin on Robinhood Chain. Gas is paid in ETH.

  5. Retry with proof

    The same request goes out again with an X-Payment header that points at the payment.

  6. Data + receipt

    The gate verifies, lifts and returns 200 OK with the data and an on-chain receipt for the books.

Agent rules

Four rules.Any fail, no pay.

Checked on the agent's side before a payment is signed. Planned for the SDK at launch.

Rule 01

Per-call cap

Refuse any single quote above a set price.

Rule 02

Daily cap

Stop paying once the day's budget is spent.

Rule 03

Allowlist

Only pay for endpoints and pay-to addresses you approved.

Rule 04

Kill switch

Freeze one agent, or all of them, instantly.

Quote anatomy

Read theticket.

Hover a field to see what it does. Field names are a draft and may change.

{
  "price": "0.001",
  "asset": "USD stablecoin",
  "chainId": 4663,
  "payTo": "0x7A3c…9F02",
  "nonce": "q_8f21…",
  "expiresIn": "30s"
}  // sample
price
What this one call costs, as a decimal string in the asset's units.
asset
The USD stablecoin the toll is paid in.
chainId
Robinhood Chain, 4663. Payments on any other chain are ignored.
payTo
The address that receives the toll. Check it against your allowlist.
nonce
Ties the payment to this quote so it can only be used once.
expiresIn
After 30 seconds the quote is void. Ask again for a fresh one.
